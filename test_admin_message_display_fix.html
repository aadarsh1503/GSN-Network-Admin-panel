🔧 Admin Message Display Fix Test

This test verifies that admin messages now show "Admin" instead of "System" in the business user panel.

📋 Changes Made

  • BusinessMessages.jsx: Updated sender name display logic to check msg.sender_role === 'admin'
  • CompanyMessages.jsx: Fixed sender name and role detection
  • MessagesPage.jsx: Updated sender name display
  • UserMessages.jsx: Fixed sender name display
  • businessController.js: Enhanced conversation queries to include sender_role and proper display names

🛠️ Technical Details

Frontend Changes:

// OLD CODE: {msg.sender_name === 'Platform Admin' || msg.sender_name?.includes('Admin') ? 'Admin' : (msg.sender_display_name || msg.sender_name || 'User')} // NEW CODE: {msg.sender_role === 'admin' ? 'Admin' : (msg.sender_display_name || msg.sender_name || 'User')}

Backend Changes:

// Enhanced SQL query to include sender_role: SELECT m.*, sender.name as sender_name, sender.role as sender_role, receiver.role as receiver_role FROM messages m JOIN users sender ON m.sender_id = sender.id JOIN users receiver ON m.receiver_id = receiver.id // Enhanced message processing: const enhancedMessages = rows.map(msg => ({ ...msg, sender_display_name: msg.sender_role === 'admin' ? 'Admin Support' : msg.sender_name, receiver_display_name: msg.receiver_role === 'admin' ? 'Admin Support' : msg.receiver_name }));

✅ Expected Results

  • ✓ Welcome messages from admin now show "Admin" instead of "System"
  • ✓ All admin messages in business panel display "Admin" as sender
  • ✓ Role-based display works consistently across all message components
  • ✓ Backend properly includes sender_role in all message queries
  • ✓ Conversation lists show "Admin Support" for admin users

🧪 How to Test

  1. Create a new business user account
  2. Check the business messages panel
  3. Verify the welcome message shows "Admin" as sender
  4. Send a message from admin to business user
  5. Confirm admin messages display "Admin" not "System"

📝 Summary

The issue was that the frontend components were checking the admin user's actual name (which could be "System") instead of checking the user's role. Now all message components properly check sender_role === 'admin' and display "Admin" for any user with admin role, regardless of their actual name in the database.
